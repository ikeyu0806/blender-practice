# Blender レッスン制作

このリポジトリは、開発者が Blender を理解して人物・モンスター・背景モデルを自分で作れるようになる練習プロジェクト。学習者が結果を**予測・観察・説明・変更**できる教材を作る。

## 最初に確認するもの

- [README.md](../../../README.md) と [ロードマップ](../../../docs/plan/README.md) で到達点と現在地を確認する。
- [レッスン規約](../../../lessons/README.md) と直近の関連レッスンで、フォルダ形式、前提、説明の粒度を確認する。
- 新しい Blender 用語を導入する場合は [用語集](../../../docs/glossary.md) の既存説明と照らし、必要なら具体例とともに更新する。
- この会話で分かった理解度や希望題材を優先する。予定番号は候補なので、必要なら橋渡しの小レッスンを挟む。
- Unity の比喩は学習者が Unity を知っている場合に限り補助として使う。まず Blender の画面・用語・データ関係だけで説明する。Unity 連携はロードマップの選択レッスンを参照する。

## レッスンを追加・編集するとき

1. 主概念と観察できる結果を絞る。人物・モンスター・背景につながる具体物を使い、初学者向けには一度に多くの新概念を入れない。
2. `lessons/NN_short_topic/` に `lesson.py` と `README.md` をそろえる。既存レッスンの番号は変更しない。追加後は `lessons/README.md` と、必要に応じてロードマップの実装状態を更新する。
3. `lesson.py` は単独で実行できるようにし、重要な処理には「何をしているか」に加えて「なぜ必要か」「結果をどこで観察するか」を日本語コメントで書く。データ API と UI 操作の関係、Transform とデータブロックの違いなど、誤解しやすい境界を説明する。生成物は `output/` に置く。
4. `README.md` に目標、前提、実行コマンド、仕組みの詳しい解説、画面とログの観察手順、値を1つ変える実験、完了条件、次の学習への接続を書く。保存して終わる教材では `--background --python` を標準の実行方法として先に示し、生成した `.blend` を GUI で開く手順を書く。画面付き `--python` は観察用の選択肢とし、スクリプト終了後もターミナルが Blender の終了を待つ理由を説明する。GUI 編集はソースへ同期しないこと、再実行で出力を上書きし得ること、シーンを初期化する場合や外部ファイルが必要な場合も明記する。共通の説明は [スクリプトと画面の関係](../../../docs/notes/script-workflow.md) にリンクする。
5. 利用可能な Blender で背景実行し、期待するデータ関係と保存結果を確認する。Blender がない場合は構文など可能な範囲を確認し、未実行であることを報告する。バージョン依存の API は実環境で確かめる。
6. 関連ファイルの差分を確認し、学習内容ごとのまとまりで Git commit する。ユーザーの既存変更は混ぜない。

## Blender について質問されたとき

まず会話で直接答える。このプロジェクトの学習に関わる質問なら、同じ作業の中で回答を文書にも残す。

- 特定のレッスンに紐づく疑問は、その `README.md` の「理解メモ」に質問、結論、確認方法を追記する。
- 複数のレッスンに関わる概念は `docs/notes/<topic>.md` にまとめ、[docs/notes/README.md](../../../docs/notes/README.md) の一覧と関連レッスンからリンクする。
- 既存の説明が誤解を招くと分かったら、元の説明も直す。スクリプトの結果に関わる回答なら、実際に検証してから記録する。
- 文書の更新も小さな Git commit にまとめる。プロジェクトと無関係な一般質問は、不要なファイル変更をしない。

教材が増えても、同じ説明の複製を避ける。各レッスンにはその回に必要な最小限の説明を置き、詳しい共通知識へリンクする。
